# 实训 9：可靠性与边界条件处理

## 先列故障，再写恢复

代码见 `fault.*` 与 `Examples/lab9.c`。`FaultManager` 保存当前故障位和出现次数；故障处理遵循“检测 → 隔离 → 报告 → 限速重试 → 验证恢复”。

| 故障 | 检测 | 安全动作 | 恢复 |
|---|---|---|---|
| SD 卡拔出 | FatFs/SPI 返回错误 | 停止写入，保留系统运行 | 每 1 s 尝试重新挂载 |
| SD 卡满 | 剩余空间/写入错误 | 停止采集或覆盖策略 | 用户清理后确认 |
| UART 半帧 | 接收超时 | 丢弃当前帧 | 从下一帧头继续 |
| 配置损坏 | magic/checksum/范围 | 使用默认值并告警 | 重新保存有效配置 |
| ADC 超时 | HAL 超时 | 放弃本次样本 | 下一周期再试，连续失败升级 |
| 意外复位 | 读取复位原因 | 记录原因 | 有限次数重启，避免循环 |

不要无限紧密重试：它会占满 CPU 和串口。示例中 SD 重试至少间隔 1 s。写文件期间掉电只能靠 `f_sync` 缩小风险，真正产品还需掉电检测、事务文件或冗余记录。

## 边界测试清单

1. 采集中拔卡、插回；系统其余功能仍应响应。
2. 文件接近满、目录损坏、文件只读。
3. UART 连续噪声、半帧、错误 CRC、长时间无数据。
4. 参数写入中断电，重启后不得接受半写数据。
5. 最低/最高采样率、ADC 0 V/接近 VDDA。
6. 看门狗复位后记录复位原因，不可反复破坏 SD 文件。

万用表观察掉电斜率和供电恢复，示波器同时看电源与调试 GPIO，能把“程序什么时候停止写”与实际电压对应起来。
